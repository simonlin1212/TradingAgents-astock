# TradingAgents-Astock 二次开发路线图

> 目标：从"被动单标的分析"升级为"**可执行的投研+持仓管理+批量筛选**"。
> 原则：小块快迭代，每个里程碑独立可验收，不阻塞整体。

## 三个需求 → 里程碑映射

| 需求 | 里程碑 | 说明 |
|------|--------|------|
| 推荐购买时给出价位、仓位 | **M1 执行建议** | 决策链尾部新增 Execution Advisor，输出买入区间/止损/目标/仓位 |
| 已持仓标的的操作指导 | **M2 持仓管理** | 输入持仓 → 注入分析 → 输出持有/加仓/减仓/清仓建议 |
| 按筛选条件批量分析全量标的 | **M3 筛选器** | 纯数据层 scanner：条件 → 标的池 |
| （接 M3）批量逐个分析并汇总决策 | **M4 批量分析** | 标的池 → 逐个跑图 → 汇总排序报告 |

## 依赖关系

```
M1（执行建议） ──► M2（持仓管理）     # M2 需要 M1 的价位/仓位输出
M3（筛选器）  ──► M4（批量分析）     # M4 消费 M3 的标的池
M1 ──► M4（可选）                    # 批量汇总表展示 M1 的执行建议
```

M3 是纯数据层、零 LLM、不依赖 M1/M2，可随时独立先行。

## 推荐实施顺序与预估

| 顺序 | 里程碑 | 预估 | 核心交付 |
|------|--------|------|----------|
| 1 | M1 执行建议 | 1-2 天 | `ExecutionAdvice` schema + 新节点 + 报告章节 + 测试 |
| 2 | M2 持仓管理 | 1-2 天 | `holdings` 输入 + 持仓感知 prompt + 持仓操作输出 |
| 3 | M3 筛选器 | 1 天 | `tradingagents/scanner/` + clist 泛化 + 筛选 CLI |
| 4 | M4 批量分析 | 2-3 天 | `tradingagents scan` 子命令 + 批量编排 + 汇总报告 |

## 关键决策点（实施前需用户拍板）

- **D1 价位/仓位的定位**：研究参考区间（推荐，契合项目"研究与教学"免责声明，需同步更新提示词与报告免责声明）vs 强策略信号。
- **D2 持仓来源**：手动输入（CLI 交互/Web 表单/JSON 文件，推荐先做）vs 对接券商/雪球同步。
- **D3 批量规模与成本**：每批默认上限（建议 5）、是否提供"核心分析师快速模式"（每次分析 30-50 次 LLM 调用，5 标的 ≈ 150-250 次，需预估费用）。
- **D4 仓位模型参数**：单票风险预算%（建议 1-2）、单票仓位上限（建议 20%）、总资金输入方式。

## 全项目通用注意事项

- 东财调用一律走 `_em_get()`（M3/M4 批量场景设 `EM_MIN_INTERVAL=1.5~2`）
- `safe_ticker_component` 是路径安全边界，批量输入必须逐个过校验
- 每次分析 30-50 次 LLM 调用——批量必须给成本预估与上限
- 改动前 `python -m pytest tests/ -v`；新 schema/节点配单元测试
- 决策链现状（实施前的基线事实）见 `m1-execution-advice.md`「现状依据」
